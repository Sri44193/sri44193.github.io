AI agents vs traditional automation

From "follow the script" to "look, decide, adapt" 🎬 Introduction to AI agents · 📄 AI agent fundamentals

🧒 Plain English Traditional automation is a program that follows instructions exactly. It does the same thing every time and can't handle a case nobody coded for (a payroll program can't cope with an exception nobody wrote a rule for). An AI agent is software that observes what's going on, makes its own decisions, and changes its approach as it learns. A support chatbot that notices a customer is frustrated and softens its reply is behaving like an agent; a fixed FAQ bot is not.
🎯 Analogy A vending machine vs a shop assistant. The vending machine (automation) gives item B4 when you press B4, nothing more. The shop assistant (agent) notices you look lost, asks what you need, and suggests something else when B4 is sold out.

Fixed decision tree vs the agent's perceive → decide → act → learn loop
Perception-action loop
The cycle every agent runs: perceive its environment (the user's message, data), process it, act (reply, call a tool), then perceive the result. The course demo calls this the loop that "defines how an agent interacts with the world".
Environment
Everything the agent can sense or affect: the conversation, documents, systems it can call.
🧩 Example from the course In the Foundry Agents page the instructor opens three ready-made agents (a pizza-ordering agent, a bank's financial assistant, an emotional-support companion) and clicks Try in playground on each. Typing a question into the User query box and watching the reply is one turn of the perception-action loop.
➕ Not in the course: what "agent" means today In current LLM products, "agent" usually means a language model + instructions + tools + a loop that lets it take several steps (search, call an API, check the result) before answering. Keep that in mind: the course's early demos are mostly chat replies, and real "agentic" behaviour (tools, multi-step plans) grows through the later courses in this series.
❓ Check yourself
A script renames invoice files using a fixed pattern. Agent or automation?
Automation: same input → same action, no observing, deciding or adapting.
Name the four steps of the loop.
Perceive → process/decide → act → (observe the result and learn), then round again.

Four characteristics: autonomy, reactivity, proactivity, learning

The checklist that separates an agent from a script 📄 AI agent fundamentals

🧭 Autonomy

Decides and acts without a human stepping in. An assembly-line robot that spots a misplaced part and fixes it, instead of waiting for a technician.

⚡ Reactivity

Responds quickly to new information. A smart thermostat reacting to people entering the room or the weather outside, not only to a manual setting.

🔭 Proactivity

Plans ahead to get a better future result. Logistics AI predicting traffic jams from history and re-routing before they happen.

📈 Learning

Improves from data and feedback over time. Translation tools that got better by learning from millions of human corrections.

🎯 Analogy A good new team member: works without hand-holding (autonomy), answers a production alert fast (reactivity), flags next sprint's risk early (proactivity), and gets better every retro (learning).
🧪 Testing angle Each characteristic suggests a test. Autonomy: does it finish the task without asking needless questions, and does it stop when it should? Reactivity: does it update when the user changes their mind mid-chat? Proactivity: does it offer the sensible next step? Learning: after a knowledge update, do old wrong answers disappear (a regression check)?
⚠️ Common trap "Learning" in a chat agent rarely means the model retrains itself live. Usually it means the team improves prompts, knowledge or models from feedback. Don't write a test that expects the agent to remember yesterday's correction unless memory was actually built in.

Three agent types: reactive, deliberative, hybrid

Speed vs depth vs balance 🎬 Introduction to AI agents · 🎬 Seeing agents in action · 📄 AI agent fundamentals

🧒 Plain English Reactive agents answer the immediate input with no memory of the past: fast and predictable, but shallow. Deliberative ("planning") agents keep a memory and a model of their world, weigh possible outcomes, then pick the best action: thorough, but slower and hungrier for data and compute. Hybrid agents switch between the two: quick for simple things, careful when it matters.

🧪 Testing angle The type tells you what to measure. Reactive: latency and consistency (same question → same answer). Deliberative: reasoning quality on multi-part questions, plus a latency budget. Hybrid: does it pick the right mode? Give it a trivial and a complex question and check it doesn't over-think the first or rush the second.
➕ Not in the course: look under the hood In the demos all three "types" are the same kind of thing: a GPT model with different instructions. The behaviour difference comes from the prompt and setup, not a different engine. The reactive/deliberative/hybrid split is a classic AI textbook idea; treat it as a design vocabulary ("how much should this agent think before acting?") rather than three products you install.
❓ Check yourself
A hotel wants instant answers to "what's the Wi-Fi password?" and careful help planning a wedding. Which type?
Hybrid: reactive speed for the FAQ, deliberative planning for the wedding.
Why is a smoke detector reactive, not deliberative?
It reacts to the current input (smoke now) with no memory of past levels and no reasoning about causes.
What's the main cost of a deliberative agent?
More data and processing → slower responses (and usually higher cost).

Risks, debates and good practice

Why agents need oversight 📄 AI agent fundamentals

🔒 Privacy

Agents need lots of data, which is sensitive in healthcare and banking.

⚖️ Bias & reliability

Trained on poor or biased data, an agent makes wrong or unfair decisions.

👷 Jobs

Routine roles shrink; supporters say people move to creative, complex work. Most winners blend humans and AI.

✅ Best practice

Audit AI decisions regularly and be transparent about how the system works, to keep trust.

🧪 Testing angle "Regular auditing" is a QA job: sample real conversations, check answers against policy, and track fairness by user group (language, region, account type). Write it down as a recurring test activity, not a one-off review.
📌 Remember The course's stance: agents are powerful, but the safe pattern is human + AI, with audits and transparency.

Why Azure AI Foundry?

Four reasons the course gives 🎬 Why Azure AI Foundry

🧒 Plain English Azure AI Foundry is Microsoft's web portal and toolkit for building AI apps and agents. Instead of stitching together separate services, you pick a model, test it, build an agent, trace and monitor it, and deploy it, all in one place.

1️⃣ One end-to-end place

Model selection → prototyping → deployment → evaluation, tracing and monitoring.

2️⃣ No-code to pro-code

Start in the Playground (no code); click View code to get a starter script for VS Code when you're ready.

3️⃣ Enterprise security

The sample code signs in with your Microsoft account, not a pasted API key, and calls a project endpoint that keeps traffic inside your Azure project.

4️⃣ Microsoft ecosystem

An agent's Knowledge → Add can connect sources like SharePoint and Microsoft Fabric.

🎯 Analogy Like a fully equipped test lab: the parts shelf (models), a bench to try things (playground), an assembly area (agents), project folders (projects) and a shipping dock (deployments) under one roof, with a security guard at the door.
🧪 Testing angle Keyless sign-in matters for test automation too: your test suites should authenticate the same way (an identity, not a key copied into a config file). If a test repo contains a raw API key, that's a security defect.
➕ Not in the course: the name changed In late 2025 Microsoft renamed Azure AI Foundry to Microsoft Foundry, and the portal layout has been updated since this course was recorded. The ideas are the same; menu names and positions may differ from the videos. Your Agentic AI with Microsoft Foundry book in first-read covers the newer version.

🧪 Testing angle Use the leaderboard thinking in test planning: for each candidate model record quality score and cost per 1,000 requests on your test set. The cheapest model that passes your quality bar wins.

Hands-on with the playgrounds

Chat, translation, images, speech 🎬 Hands-on with AI capabilities

💬 Chat playground

Pick a deployment (GPT-4.1), write instructions ("You are a helpful bot in Paris acting as a tour guide"), Apply changes, then ask "Can you recommend a high-quality hotel nearby?". Swap to GPT-3.5 Turbo: faster, less detailed.

🌍 Translator playground

Text translation: Translate from = auto-detect, To = Spanish, then Japanese, for "Welcome to our hotel". Document translation translates an uploaded file.

🖼️ Images playground

DALL-E 3 deployment. Prompt: "Create an image of a hotel lobby in Paris". Settings: resolution, style (vivid or natural), quality.

🎙️ Speech playground

Real-time transcription: upload, drag in an audio file or record yourself, and get text.

📌 The course's three tips 1) Understand what each service can do. 2) Test it against your own business scenarios. 3) Keep up with Azure's new features.
🧪 Testing angle Your first manual test plan: 5 hotel questions × 2 models, same instructions. Note correctness, detail, tone and response time per answer. Translation: back-translate (Japanese → English) to spot meaning drift. Speech: try accents and background noise.
⚠️ Common trap One good-looking answer proves little. Model replies vary between runs; ask each question several times before you judge a model.
❓ Check yourself
Where do you tell the chat model to act as a Paris tour guide?
In the instructions (system message) box of the setup panel, then Apply changes.
The translator's "Translate from" is set to auto-detect. What could go wrong with a one-word input?
Short text may be detected as the wrong language, so the translation is off. A good edge-case test.

✅ One-page cheat sheet

  1. 🤖 Agent = observes, decides, adapts. Automation = follows fixed rules.
  2. 🔄 Perception-action loop: perceive → decide → act → observe the result.
  3. 🧭⚡🔭📈 Four traits: autonomy, reactivity, proactivity, learning.
  4. ⚡ Reactive = speed, no memory (FAQs). 🧠 Deliberative = depth, memory, planning (detailed inquiries). ⚖️ Hybrid = balance (multi-faceted advice).
  5. 🔒 Risks: privacy, biased data, job change. Fixes: regular audits + transparency, humans and AI together.
  6. ☁️ Foundry: one place, no-code → pro-code, keyless sign-in, Microsoft ecosystem (SharePoint, Fabric).
  7. 🧱 Five components: Model catalog → Playground → Agents → Projects → Deployments.
  8. 🗣️👁️🎙️🎛️ Services: language, vision, speech, multimodal; choose models by quality and cost (leaderboards).
  9. 🧪 Playgrounds are your first test bench: same question, different models, several runs.

Try it: the module's activities

What the course asks you to do, plus a QA twist

  1. Platform tour and setup (45 min): create your Foundry project and find all five components.
  2. Agent impact and types explorer: pick three business tasks and choose reactive, deliberative or hybrid for each, with a reason.
  3. Capability exploration and first agent: try chat, translator, images and speech; give a chat model a persona.
  4. ➕ QA twist: write a 10-row spreadsheet of test questions for your first agent (expected answer, actual, pass/fail, model, time). Re-use it in Module 4.
⚠️ Cost The course says you can finish for under $10 on the free tier. Check billing in the Azure portal, and delete deployments you no longer need.
