LangGraph, from first node to production

How the runtime actually executes your graph, every building block you'll touch, the persistence model that makes agents pausable and resumable, the multi-agent patterns, and how to test all of it.

Written against langgraph 1.2.18 (26 Oct 2026) Python ≥ 3.10 MIT licence Notes dated 29 Oct 2026
How these notes were checkedCore code blocks marked ✓ ran on 1.2.18 were executed against an installed langgraph==1.2.18 before publishing. Blocks that need a live LLM, Postgres, or a deployment are syntax-checked only. LangGraph ships patch releases several times a week, so pin your version.

01What LangGraph is

A low-level runtime for building stateful, long-running, multi-step LLM applications as graphs.

LangGraph is an open-source (MIT) orchestration framework from LangChain Inc., available for Python and JavaScript/TypeScript. You describe your application as a graph: nodes are functions that do work (call a model, run a tool, transform data), edges decide what runs next, and a shared state object flows through it all. The runtime adds what agents need and plain code makes painful: checkpointed persistence, pause-and-resume for humans, streaming, retries, and recovery after crashes.

It is deliberately not a prompt library or an agent abstraction. It doesn't hide your prompts or your control flow. That's its main design choice: you own the loop.

Where it sits in the stack

Controllable

Explicit control flow

Loops, branches, parallel fan-out and joins are edges you write and can draw, not behaviour hidden in a prompt.

Stateful

Checkpointed state

Every step saves a snapshot per thread. That gives memory, resume after failure, and time travel.

Interruptible

Human-in-the-loop

interrupt() pauses anywhere and waits — minutes or days — for a person, then resumes exactly there.

Observable

Streaming

Stream state, per-node updates, LLM tokens, custom progress events, and subgraph activity.

02When to use it (and when not)

SituationRecommendation
Single LLM call, or a fixed prompt chainPlain code or a LangChain chain. A graph is overhead.
Standard tool-calling agent (model ↔ tools loop)Start with LangChain's create_agent — it already runs on LangGraph and adds middleware. Drop to raw LangGraph when you outgrow it.

Team wants role-play agents with minimal codeHigher-level frameworks (CrewAI etc.) are quicker to start; LangGraph gives more control.

03The execution model

Understanding this one section explains almost every surprising behaviour later.

LangGraph's runtime is modelled on Google's Pregel / bulk-synchronous-parallel design. A compiled graph runs as a sequence of supersteps:

  1. Plan. Work out which nodes are triggered — those whose incoming edges fired in the previous step (or START on the first step).
  2. Execute. Run all triggered nodes in parallel. Each node sees the same state snapshot and returns a partial update — it never mutates state directly.
  3. Update. Apply every node's update to the state through each key's reducer (or overwrite, if the key has none). Updates from parallel nodes are merged in a deterministic order.
  4. Checkpoint. If a checkpointer is attached, save the new state as a checkpoint for this thread.
  5. Repeat until no nodes are triggered (the graph reached END), an interrupt fires, or the recursion limit is hit.
Consequences you will hit
  • Parallel writes to a key without a reducer raise InvalidUpdateError. If two branches both write results, give it a reducer such as operator.add.
  • A node in a parallel step can't see what its sibling wrote until the next step.
  • If one node in a superstep fails, the whole superstep fails — but successful siblings' writes are kept as pending writes and aren't re-run on resume.
  • Each superstep counts towards recursion_limit. An agent loop that never reaches END eventually raises GraphRecursionError — but with a high default (§7), so set your own.

Channels are the low-level mechanism: each state key is stored in a channel (last-value, binary-operator aggregate, topic, and from 1.2 the delta-storing DeltaChannel). You rarely touch channels directly — the StateGraph builder creates them from your state schema.

04Your first graph

shell
pip install -U "langgraph==1.2.18"           # pin; Python 3.10+
pip install langchain-openai                  # or langchain-anthropic etc., for model nodes
hello_graph.py ✓ ran on 1.2.18
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    topic: str
    draft: str
    approved: bool

def write(state: State) -> dict:
    return {"draft": f"A short note about {state['topic']}."}

def review(state: State) -> dict:
    return {"approved": len(state["draft"]) < 200}

builder = StateGraph(State)
builder.add_node("write", write)
builder.add_node("review", review)
builder.add_edge(START, "write")
builder.add_edge("write", "review")
builder.add_edge("review", END)

graph = builder.compile()
print(graph.invoke({"topic": "LangGraph"}))
# {'topic': 'LangGraph', 'draft': 'A short note about LangGraph.', 'approved': True}

print(graph.get_graph().draw_mermaid())     # diagram source for docs/PRs

The pattern never changes: define state → add nodes → add edges → compile → invoke. compile() validates the graph (no orphan nodes, valid edge targets) and is where you attach a checkpointer, store, cache and static interrupts.

05State, schemas & reducers

Reducers decide how updates merge

A node returns a partial dict. For each key, LangGraph either overwrites (default) or calls the key's reducer reducer(current, update) → new, declared with Annotated.

state_reducers.py ✓ ran on 1.2.18
import operator
from typing import Annotated, TypedDict
from langchain_core.messages import AnyMessage
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.types import Overwrite

class State(TypedDict):
    question: str                                        # overwrite
    findings: Annotated[list[str], operator.add]         # append
    messages: Annotated[list[AnyMessage], add_messages]  # append + update-by-id

def a(state): return {"findings": ["from a"]}
def b(state): return {"findings": ["from b"]}
def reset(state): return {"findings": Overwrite(["summary only"])}  # bypass reducer

g = StateGraph(State)
g.add_node("a", a); g.add_node("b", b); g.add_node("reset", reset)
g.add_edge(START, "a"); g.add_edge(START, "b")       # a and b run in parallel
g.add_edge(["a", "b"], "reset")                        # join: wait for both
g.add_edge("reset", END)
graph = g.compile()

out = graph.invoke({"question": "q", "findings": [], "messages": []})
assert out["findings"] == ["summary only"]
Built-inBehaviour
operator.addList concatenation / numeric sum
add_messagesAppends messages; a message with an existing id replaces it; RemoveMessage(id=…) deletes; accepts dict/tuple shorthand and converts to message objects
MessagesStatePrebuilt state with messages: Annotated[list[AnyMessage], add_messages]; subclass it to add keys
Overwrite(value)Returned as an update, skips the reducer and replaces the value
DeltaChannel(reducer, snapshot_frequency=…)1.2+ (beta). Stores only deltas per step with a full snapshot every N updates (default 100 since 1.2.18). Cuts checkpoint storage for ever-growing keys like long message histories.

Input, output and private schemas

StateGraph(State, input_schema=In, output_schema=Out) narrows what callers can pass and what they get back, while nodes still see the full internal state. Nodes can also declare their own input type to read a private channel that isn't part of the public state. Use this to keep scratch data (retrieved chunks, intermediate plans) out of the API contract.

Design guidanceKeep state small, serialisable and flat. Every key is written to every checkpoint, so large blobs (full documents, images) belong in object storage or the Store, with only references in state. Store raw data, not formatted prompts — format inside the node that needs it.

06Nodes & the runtime

A node is any callable — sync or async — that takes the state and returns a partial update (or a Command). Accepted signatures:

SignatureUse
def node(state)Most nodes
def node(state, runtime: Runtime[Ctx])Needs run-scoped context (user id, model choice, DB handle), the Store, a stream writer, or execution info
def node(state, config: RunnableConfig)Needs raw config (thread id, tags, callbacks)

Runtime context — dependency injection for graphs

Since 0.6, static per-run dependencies go in a typed context, declared with context_schema and passed at invoke time. They're not part of state, so they aren't checkpointed.

runtime_context.py ✓ ran on 1.2.18
from dataclasses import dataclass
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.runtime import Runtime

@dataclass
class Ctx:
    user_id: str
    model_name: str = "small-model"

class State(TypedDict):
    reply: str

def respond(state: State, runtime: Runtime[Ctx]) -> dict:
    info = runtime.execution_info          # thread_id, run_id, node_attempt, ...
    return {"reply": f"{runtime.context.user_id} via {runtime.context.model_name} (attempt {info.node_attempt})"}

g = StateGraph(State, context_schema=Ctx)
g.add_node("respond", respond)
g.add_edge(START, "respond"); g.add_edge("respond", END)
graph = g.compile()
print(graph.invoke({}, context=Ctx(user_id="u-42")))

Other runtime members: runtime.store (long-term memory), runtime.stream_writer (custom stream events), runtime.server_info (assistant/graph/user when running on Agent Server, else None), and runtime.drain_requested for graceful shutdown.

Node options on add_node

Set defaults for every node at once with builder.set_node_defaults(retry_policy=…, timeout=…, cache_policy=…, error_handler=…) (1.2+). Per-node values override; defaults don't propagate into subgraphs.

conditional_loop.py ✓ ran on 1.2.18
from typing import Literal, TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    attempts: int
    score: float

def generate(state: State) -> dict:
    n = state.get("attempts", 0) + 1
    return {"attempts": n, "score": 0.3 * n}     # pretend quality improves each try

def route(state: State) -> Literal["generate", "__end__"]:
    if state["score"] >= 0.8 or state["attempts"] >= 5:   # always bound loops yourself
        return END
    return "generate"

g = StateGraph(State)
g.add_node("generate", generate)
g.add_edge(START, "generate")
g.add_conditional_edges("generate", route)
graph = g.compile()
assert graph.invoke({"attempts": 0})["attempts"] == 3
Recursion limit — the default changedOlder docs and most tutorials say the default is 25 supersteps. In langgraph 1.2.18 the default is 10,007 (overridable with the LANGGRAPH_DEFAULT_RECURSION_LIMIT environment variable) — verified against the installed package. That is effectively no safety net for a runaway agent loop, so set one explicitly per run: graph.invoke(inputs, {"recursion_limit": 25}). Hitting it raises GraphRecursionError; treat that as a bug, since your own logic should end the loop.

08Command, Send & map-reduce

Command: update + route in one return

Return Command(update={...}, goto="node") from a node when the routing decision and the state change belong together — classic for agent hand-offs. Annotate the return type so the graph can be drawn correctly.

command_routing.py ✓ ran on 1.2.18
from typing import Literal, TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.types import Command

class State(TypedDict):
    query: str
    handled_by: str

def triage(state: State) -> Command[Literal["billing", "support"]]:
    team = "billing" if "refund" in state["query"].lower() else "support"
    return Command(update={"handled_by": team}, goto=team)

def billing(state): return {}
def support(state): return {}

g = StateGraph(State)
g.add_node("triage", triage); g.add_node("billing", billing); g.add_node("support", support)
g.add_edge(START, "triage"); g.add_edge("billing", END); g.add_edge("support", END)
graph = g.compile()
assert graph.invoke({"query": "I want a refund"})["handled_by"] == "billing"
Command fieldMeaning
updateState update, applied like a normal node return
gotoNode name, list of names, or Send(s)
graph=Command.PARENTRoute to a node in the parent graph from inside a subgraph (multi-agent hand-off). Shared keys need reducers in the parent.
resumeOnly used as input to resume after interrupt() — see §14

Command vs conditional edge: use a conditional edge when routing is a pure function of state and you want it visible as a separate decision; use Command when the node that does the work also decides where to go next.

Send: dynamic fan-out (map-reduce)

When the number of parallel branches is only known at run time — one per document, per sub-question, per file — return a list of Send(node, payload) from a router. Each Send runs the target node with its own private input; results merge back through a reducer.

map_reduce.py ✓ ran on 1.2.18
import operator
from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.types import Send

class State(TypedDict):
    docs: list[str]
    summaries: Annotated[list[str], operator.add]   # reducer collects parallel results
    final: str

class DocInput(TypedDict):
    doc: str

def fan_out(state: State):
    return [Send("summarise", {"doc": d}) for d in state["docs"]]

def summarise(item: DocInput) -> dict:
    return {"summaries": [item["doc"][:10]]}

def combine(state: State) -> dict:
    return {"final": " | ".join(sorted(state["summaries"]))}

g = StateGraph(State)
g.add_node("summarise", summarise)
g.add_node("combine", combine)
g.add_conditional_edges(START, fan_out, ["summarise"])
g.add_edge("summarise", "combine")
g.add_edge("combine", END)
graph = g.compile()
out = graph.invoke({"docs": ["alpha document", "beta document", "gamma document"], "summaries": []})
assert len(out["summaries"]) == 3

Cap fan-out with {"max_concurrency": n} in the run config when branches call rate-limited APIs.

09Retries, timeouts & error handling

LangGraph 1.2 (May 2026) turned resilience into per-node configuration.

resilience.py ✓ ran on 1.2.18
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.types import Command, RetryPolicy, TimeoutPolicy
from langgraph.errors import NodeError

class State(TypedDict):
    order_id: str
    status: str

async def charge_card(state: State) -> dict:
    raise ConnectionError("payment gateway down")      # simulate an outage

def on_charge_failed(state: State, error: NodeError) -> Command:
    # Runs only after retries are exhausted. Compensate and reroute (saga pattern).
    return Command(update={"status": "payment_failed"}, goto="notify_customer")

def notify_customer(state: State) -> dict:
    return {}

g = StateGraph(State)
g.add_node(
    "charge_card", charge_card,
    retry_policy=RetryPolicy(max_attempts=3, initial_interval=0.01, retry_on=ConnectionError),
    timeout=TimeoutPolicy(run_timeout=30, idle_timeout=10),
    error_handler=on_charge_failed,
    destinations=("notify_customer",),
)
g.add_node("notify_customer", notify_customer)
g.add_edge(START, "charge_card"); g.add_edge("charge_card", END); g.add_edge("notify_customer", END)
graph = g.compile()

import asyncio
print(asyncio.run(graph.ainvoke({"order_id": "A1"})))    # {'order_id': 'A1', 'status': 'payment_failed'}
MechanismScopeNotes
RetryPolicyPer node or via set_node_defaultsmax_attempts, initial_interval, backoff_factor, max_interval, jitter, retry_on (exception types or predicate). Retry transient errors only.
TimeoutPolicyPer node, async onlyrun_timeout caps one attempt; idle_timeout resets on progress, so it catches stalls without killing a healthy stream. Raises NodeTimeoutError (retryable by default); the timed-out attempt's writes are discarded.
error_handlerPer nodefn(state, error: NodeError) → Command, after retries. Python only.
Graceful drainPer runRunControl().request_drain() (any thread) with invoke(..., control=rc): the run stops after the current superstep, checkpoints, and raises GraphDrained. Re-invoke on the same thread to continue. Use for deploys and autoscaling.
Error in stateDesign patternFor expected failures (tool returned "not found"), return the error as data and let routing decide — don't raise.

streaming.py ✓ ran on 1.2.18
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.config import get_stream_writer

class State(TypedDict):
    n: int

def work(state: State) -> dict:
    writer = get_stream_writer()
    for pct in (25, 50, 100):
        writer({"progress": pct})
    return {"n": state["n"] + 1}

g = StateGraph(State); g.add_node("work", work)
g.add_edge(START, "work"); g.add_edge("work", END)
graph = g.compile()

# Multiple modes, typed v2 parts (1.1+): each part has type, ns, data
for part in graph.stream({"n": 0}, stream_mode=["updates", "custom"], version="v2"):
    print(part["type"], part["data"])
# custom {'progress': 25} ... updates {'work': {'n': 1}}

result = graph.invoke({"n": 0}, version="v2")
print(result.value, result.interrupts)          # {'n': 1} ()

Pass subgraphs=True to stream to also see events from nested graphs; each chunk then carries a namespace tuple telling you which subgraph produced it.

v1 vs v2 outputsv2 (opt-in, 1.1+) gives typed stream parts and a GraphOutput from invoke. Dict-style access on GraphOutput (result["__interrupt__"]) is deprecated and planned for removal in LangGraph 3.0. New code should use version="v2" and result.value / result.interrupts.

11Persistence: checkpointers & threads

Compile with a checkpointer and every superstep is saved as a checkpoint under a thread. A thread is one conversation or job, identified by thread_id in the config. This one feature unlocks multi-turn memory, human-in-the-loop, time travel and fault tolerance.

CheckpointerPackageUse for
InMemorySaverlanggraph (built in)Tests, notebooks. Lost on restart.
SqliteSaver / AsyncSqliteSaverlanggraph-checkpoint-sqliteLocal apps, single-process tools
PostgresSaver / AsyncPostgresSaverlanggraph-checkpoint-postgresProduction. Call .setup() once to create tables; supports prune (3.2+)
Community saversRedis, MongoDB, othersMatch your existing infrastructure
threads.py ✓ ran on 1.2.18
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.checkpoint.memory import InMemorySaver

def echo_bot(state: MessagesState) -> dict:
    turns = sum(1 for m in state["messages"] if m.type == "human")
    return {"messages": [("ai", f"You've sent {turns} message(s).")]}

g = StateGraph(MessagesState)
g.add_node("bot", echo_bot)
g.add_edge(START, "bot"); g.add_edge("bot", END)
graph = g.compile(checkpointer=InMemorySaver())

alice = {"configurable": {"thread_id": "alice"}}
bob   = {"configurable": {"thread_id": "bob"}}
graph.invoke({"messages": [("human", "hi")]}, alice)
out = graph.invoke({"messages": [("human", "again")]}, alice)
assert out["messages"][-1].content == "You've sent 2 message(s)."   # remembered
out = graph.invoke({"messages": [("human", "hello")]}, bob)
assert out["messages"][-1].content == "You've sent 1 message(s)."   # isolated
production checkpointer (Postgres)
from langgraph.checkpoint.postgres import PostgresSaver

DB_URI = "postgresql://user:pass@host:5432/agents"
with PostgresSaver.from_conn_string(DB_URI) as checkpointer:
    checkpointer.setup()                  # once per deploy/migration, from one process
    graph = builder.compile(checkpointer=checkpointer)
    graph.invoke(inputs, {"configurable": {"thread_id": "order-4471"}})

Durability modes

Choose how strictly checkpoints are written with durability= on invoke/stream:

ModeBehaviourTrade-off
"exit"Persist only when the run finishes, errors or interruptsFastest; can't recover mid-run after a crash
"async"Persist each step asynchronously while the next step runsGood balance; tiny risk of losing the last step on a hard crash
"sync"Persist each step before the next beginsStrongest guarantee; slower

12Inspecting state & time travel

time_travel.py ✓ ran on 1.2.18
config = {"configurable": {"thread_id": "t1"}}
graph.invoke(inputs, config)

QA useTime travel turns a production bug into a reproducible test: pull the thread, find the checkpoint before things went wrong, replay or fork it with a fix. update_state(..., as_node=...) is also the core of partial-graph testing (§21).

13Long-term memory: the Store

Checkpoints are per thread (short-term memory). The Store is cross-thread key-value memory — user preferences, learned facts, profiles — organised by namespace tuples, with optional semantic search when configured with an embedding index.

store_memory.py ✓ ran on 1.2.18
from dataclasses import dataclass
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.runtime import Runtime
from langgraph.store.memory import InMemoryStore
from langgraph.checkpoint.memory import InMemorySaver

@dataclass
class Ctx:
    user_id: str

def remember_and_reply(state: MessagesState, runtime: Runtime[Ctx]) -> dict:
    ns = ("users", runtime.context.user_id, "prefs")
    last = state["messages"][-1].content
    if last.startswith("I prefer "):
        runtime.store.put(ns, "style", {"value": last.removeprefix("I prefer ")})
    item = runtime.store.get(ns, "style")
    style = item.value["value"] if item else "unknown"
    return {"messages": [("ai", f"Style: {style}")]}

g = StateGraph(MessagesState, context_schema=Ctx)
g.add_node("reply", remember_and_reply)
g.add_edge(START, "reply"); g.add_edge("reply", END)
graph = g.compile(checkpointer=InMemorySaver(), store=InMemoryStore())

ctx = Ctx(user_id="u1")
graph.invoke({"messages": [("human", "I prefer bullet points")]}, {"configurable": {"thread_id": "a"}}, context=ctx)
out = graph.invoke({"messages": [("human", "hi")]}, {"configurable": {"thread_id": "b"}}, context=ctx)
assert out["messages"][-1].content == "Style: bullet points"    # new thread, same user

14Human-in-the-loop

Call interrupt(payload) inside a node. The run stops, the checkpoint is saved, and payload is returned to the caller. Later — even days later, from another process — invoke with Command(resume=value) on the same thread; interrupt() returns value and the node continues.

approval.py ✓ ran on 1.2.18
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.types import interrupt, Command
from langgraph.checkpoint.memory import InMemorySaver

class State(TypedDict):
    amount: float
    status: str

def request_approval(state: State) -> dict:
    if state["amount"] < 100:
        return {"status": "auto-approved"}
    decision = interrupt({"question": "Approve refund?", "amount": state["amount"]})
    return {"status": "approved" if decision == "yes" else "rejected"}

g = StateGraph(State)
g.add_node("approve", request_approval)
g.add_edge(START, "approve"); g.add_edge("approve", END)
graph = g.compile(checkpointer=InMemorySaver())           # required for interrupts

cfg = {"configurable": {"thread_id": "refund-9"}}
first = graph.invoke({"amount": 250.0}, cfg, version="v2")
assert first.interrupts[0].value["amount"] == 250.0      # paused, payload for the UI

final = graph.invoke(Command(resume="yes"), cfg, version="v2")
assert final.value["status"] == "approved"

Common HITL patterns

Approve / reject

Gate a risky action

Interrupt before a tool that sends email, moves money or deletes data; route on the answer.

Edit state

Fix the draft

Show the draft or tool arguments; resume with corrected values and write them to state.

Review tool calls

Human checks the plan

Before a ToolNode runs, surface the model's tool calls for accept, edit or respond.

Ask for input

Clarifying question

Agent needs a missing detail; validate the answer and loop back via a conditional edge if invalid.

Rules that cause real bugs
  • The node re-runs from the top on resume. Code before interrupt() executes twice — keep it idempotent, and put side effects after the interrupt or in a later node.
  • Never wrap interrupt() in a bare try/except — it works by raising a special exception, and you'll swallow it.
  • Resume values match interrupts by order within a node. Don't call interrupts conditionally in a way that changes between runs.
  • Payloads must be JSON-serialisable.
  • Several parallel interrupts: resume with a dict mapping each interrupt id to its answer.
  • interrupt(..., response_schema=Model) (1.2.12+) validates the resume value with Pydantic/TypedDict/dataclass.
  • Static interrupt_before/interrupt_after exist for debugging; the docs recommend interrupt() for real HITL.

15Durable execution

With a checkpointer, a crashed or drained run resumes from its last checkpoint rather than restarting. To make that safe:

  • Determinism on replay: a resumed node re-executes from its start. Anything non-deterministic or side-effecting (random IDs, timestamps, API writes) should be wrapped in a @task (functional API) or isolated in its own node, so its result is checkpointed and reused instead of recomputed.
  • Idempotency: design external writes so repeating them is harmless (idempotency keys, upserts).
  • Pending writes: if one parallel node fails, its successful siblings' outputs are kept and not re-run on resume.
  • Pick durability per workload: "sync" for payments, "async" for chat, "exit" for cheap batch jobs.

16Functional API

An alternative to building graphs: decorate a normal Python function with @entrypoint and its durable sub-steps with @task. You get checkpointing, interrupts and streaming while writing ordinary if/for code. Calling a task returns a future; .result() waits for it, and calling several before waiting runs them in parallel.

functional_api.py ✓ ran on 1.2.18
from langgraph.func import entrypoint, task
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import interrupt, Command

@task
def draft(topic: str) -> str:
    return f"Draft about {topic}"          # result is checkpointed; not re-run on resume

@task
def score(text: str) -> int:
    return len(text)

@entrypoint(checkpointer=InMemorySaver())
def workflow(topic: str) -> dict:
    text = draft(topic).result()
    futures = [score(text), score(text.upper())]   # run in parallel
    scores = [f.result() for f in futures]
    ok = interrupt({"review": text})                # human review
    return {"text": text, "scores": scores, "approved": ok}

cfg = {"configurable": {"thread_id": "f1"}}
for _ in workflow.stream("agents", cfg): pass
print(workflow.invoke(Command(resume=True), cfg))
Graph APIFunctional API

Best forAgents, branching workflows, team-readable designsAdding durability/HITL to existing code quickly

The two interoperate: a task can invoke a compiled graph, and a graph node can call an entrypoint. entrypoint.final(value=…, save=…) lets you return one thing to the caller while saving another as the persisted state for the next run.

17Subgraphs

A compiled graph can be a node in another graph. Use subgraphs to encapsulate a team's agent, reuse a workflow, or test a section in isolation.

subgraph.py ✓ ran on 1.2.18
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class ResearchState(TypedDict):
    question: str
    notes: str

def dig(state: ResearchState) -> dict:
    return {"notes": f"notes on {state['question']}"}

sub = StateGraph(ResearchState); sub.add_node("dig", dig)
sub.add_edge(START, "dig"); sub.add_edge("dig", END)
research = sub.compile()

class AppState(TypedDict):
    user_query: str
    answer: str

def call_research(state: AppState) -> dict:      # explicit mapping between schemas
    out = research.invoke({"question": state["user_query"]})
    return {"answer": out["notes"]}

app = StateGraph(AppState); app.add_node("research", call_research)
app.add_edge(START, "research"); app.add_edge("research", END)
assert app.compile().invoke({"user_query": "LangGraph"})["answer"] == "notes on LangGraph"

Subgraph persistence: by default a subgraph inherits the parent's checkpointer. Compile a subgraph with checkpointer=True if it needs its own persistent memory across invocations (e.g. a sub-agent that remembers its own conversation). Inspect nested state with graph.get_state(config, subgraphs=True).

18Agents & tools

The canonical agent is a loop: the model decides whether to call tools; if it does, run them and feed the results back; stop when the model answers directly.

react_agent.py (needs a tool-calling chat model)
from langchain_core.tools import tool
from langchain.chat_models import init_chat_model
from langgraph.graph import StateGraph, MessagesState, START
from langgraph.prebuilt import ToolNode, tools_condition
from langgraph.checkpoint.memory import InMemorySaver

@tool
def get_order_status(order_id: str) -> str:
    """Look up the shipping status of an order."""
    return f"Order {order_id} shipped yesterday."

tools = [get_order_status]
llm = init_chat_model("anthropic:claude-sonnet-4-5").bind_tools(tools)   # any provider

def call_model(state: MessagesState) -> dict:
    return {"messages": [llm.invoke(state["messages"])]}

g = StateGraph(MessagesState)
g.add_node("model", call_model)
g.add_node("tools", ToolNode(tools))
g.add_edge(START, "model")
g.add_conditional_edges("model", tools_condition)      # → "tools" or END
g.add_edge("tools", "model")
agent = g.compile(checkpointer=InMemorySaver())

agent.invoke({"messages": [("human", "Where is order 4471?")]},
             {"configurable": {"thread_id": "c1"}, "recursion_limit": 20})

Deprecationlanggraph.prebuilt.create_react_agent is deprecated since LangGraph 1.0 in favour of langchain.agents.create_agent, which adds a middleware system (human-in-the-loop, summarisation, PII handling, model/tool call hooks). ToolNode and tools_condition remain in langgraph.prebuilt. MessageGraph is gone — use StateGraph(MessagesState).

Tools that update state

A tool can return a Command to update graph state (for example, to record the authenticated user or hand off to another agent). It must include a ToolMessage in the messages update so the model's tool call gets a reply. Tools can read graph state and the Store via injected arguments (InjectedState, InjectedStore, or a ToolRuntime parameter in LangChain 1.x) that the model never sees.

20Deployment & observability

Self-hosting

A compiled graph is just a Python object. You can serve it from FastAPI, a worker queue or a CLI, backed by a Postgres checkpointer and store. You then own threads, concurrency, streaming over HTTP, background runs and scaling.

LangSmith Deployment (formerly LangGraph Platform)

Renamed in October 2025. It runs your graphs on an Agent Server that provides assistants (versioned configs of a graph), threads, background runs, task queues, crons, webhooks, streaming, auth, and MCP/A2A endpoints, with Studio as a visual debugger. Options span cloud, hybrid and self-hosted.

Set LANGSMITH_TRACING=true and LANGSMITH_API_KEY and every run is traced as a tree of node, LLM and tool spans. LangGraph also exports OpenTelemetry-compatible traces, and evaluation tools such as DeepEval integrate through LangChain's callback handler (see the DeepEval notes).

Design for testability

  • Build graphs in a factory — build_graph(model, tools, checkpointer) — so tests inject fakes. The docs recommend compiling inside each test with a new checkpointer.
  • Keep routers as pure functions of state.
  • Put the LLM call in a thin node; put parsing and business logic in separately testable functions.
tests/test_graph.py ✓ ran on 1.2.18
import pytest
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import interrupt, Command

class State(TypedDict, total=False):
    text: str
    label: str
    reviewed: bool

# --- production code (normally in src/) ---
def route(state: State) -> str:
    return "review" if state["label"] == "risky" else END

def build_graph(classify, checkpointer=None):
    def classify_node(state): return {"label": classify(state["text"])}
    def review(state): return {"reviewed": interrupt({"text": state["text"]})}
    g = StateGraph(State)
    g.add_node("classify", classify_node); g.add_node("review", review)
    g.add_edge(START, "classify")
    g.add_conditional_edges("classify", route, ["review", END])
    g.add_edge("review", END)
    return g.compile(checkpointer=checkpointer)

# --- tests ---
fake_classifier = lambda text: "risky" if "wire" in text else "safe"   # stands in for the LLM

@pytest.mark.parametrize("label,expected", [("risky", "review"), ("safe", END)])
def test_router(label, expected):
    assert route({"label": label}) == expected

def test_node_in_isolation():
    graph = build_graph(fake_classifier)
    assert graph.nodes["classify"].invoke({"text": "wire $5k"}) == {"label": "risky"}

def test_path_for_safe_input():
    graph = build_graph(fake_classifier)
    visited = [k for chunk in graph.stream({"text": "hello"}, stream_mode="updates") for k in chunk]
    assert visited == ["classify"]

def test_risky_input_pauses_then_resumes():
    graph = build_graph(fake_classifier, checkpointer=InMemorySaver())
    cfg = {"configurable": {"thread_id": "t"}}
    paused = graph.invoke({"text": "wire $5k"}, cfg, version="v2")
    assert paused.interrupts[0].value == {"text": "wire $5k"}
    assert graph.get_state(cfg).next == ("review",)
    done = graph.invoke(Command(resume=True), cfg, version="v2")
    assert done.value["reviewed"] is True

def test_partial_execution_from_midpoint():
    graph = build_graph(fake_classifier, checkpointer=InMemorySaver())
    cfg = {"configurable": {"thread_id": "p"}}
    graph.update_state(cfg, {"text": "x", "label": "safe"}, as_node="classify")
    graph.invoke(None, cfg)                       # runs only what follows "classify"
    assert "reviewed" not in graph.get_state(cfg).values

Faking the model

For nodes that call a chat model, inject a fake from langchain_core.language_models.fake_chat_models — for example GenericFakeChatModel(messages=iter([AIMessage(...)])) returns scripted messages, including ones carrying tool_calls, so you can drive the agent loop deterministically. Keep real-model runs for the evaluation layer.

Test checklist for any graph

  • Every conditional edge has a test per branch, including the loop exit
  • Loops have an explicit bound that's tested, independent of recursion_limit
  • Keys written by parallel nodes have reducers, and a test runs them in parallel
  • Each interrupt() has a pause test and a resume test per answer type, and side effects don't duplicate on resume
  • Two threads in one test prove isolation
  • Failure injection: retry exhausted → error handler → correct route
  • Serialisation: state survives a round trip through the production checkpointer (no un-serialisable objects)
  • Agent-level evals run on a pinned model with a fixed dataset

23Pitfalls & anti-patterns

✗

Mutating state in place

state["items"].append(x) bypasses reducers and checkpoints. Always return an update.

✗

No reducer on parallel keys

Two branches writing one plain key raises InvalidUpdateError.

✗

Unbounded loops

Relying on recursion_limit to stop an agent — the 1.2.x default is 10,007 steps. Add an iteration counter, a clear exit, and an explicit limit.

✗

Side effects before interrupt

They run again on resume. Move them after, or into their own node.

✗

try/except around interrupt

Swallows the pause signal; the graph never stops.

✗

Huge objects in state

Bloats every checkpoint. Store references; consider DeltaChannel for long histories.

✗

Using InMemorySaver in prod

All threads vanish on restart or across replicas.

✗

Random thread ids

Make threads unfindable. Use business keys.

✗

Too many agents too early

Each hop adds latency, cost and a failure point. Earn complexity.

✗

Floating versions

Patch releases change defaults (e.g. snapshot frequency in 1.2.18). Pin and upgrade deliberately.
